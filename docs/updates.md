# 更新

`update llama` 在没有运行时时执行首次安装，之后更新当前后端。首次安装必须给出 `--backend`；同版本只有显式 `--reinstall` 才重装，降级会拒绝。运行时目录是 `runtime/llama.cpp/<backend>/<release-tag>`，tag 长度不固定。

元数据来自 GitHub Releases。资产必须有有效大小和 SHA-256 digest；启动器归档还会与 `SHA256SUMS.txt` 交叉校验。更新前检查磁盘空间，下载后校验字节数和摘要，再进行防路径穿越、链接、特殊文件和解压体积的安全解压。

每个下载都会显示原始 HTTPS 地址、实际代理前缀地址（如有）、访问路线、资产大小、30 格进度条、百分比、已下载字节、实时速度和完成后的 SHA-256。重定向到非 HTTPS 会拒绝。可用 `LLAMALC_GITHUB_PROXY` 配置 HTTPS 下载前缀；环境代理优先，Windows 还支持当前用户的手动代理及 PAC/WPAD。代理请求失败时会明确提示原因，并对原始 GitHub 地址执行一次不走代理的直连重试。大型资产不再使用固定两分钟总超时。

启动器归档必须且只能包含 `LlamaLc/bin/llamalc[.exe]` 与 `LlamaLc/bin/llamaup[.exe]`。下载、双重摘要校验、解压和两个程序的版本探测完成后，菜单停留在“按 Enter 退出当前程序”提示，不会直接闪退。随后经校验的 `.llamaup-run-*` 独立副本等待旧进程退出，备份并替换两个程序；第二次替换失败会回滚。完成后自动启动新版，Windows 还会等待菜单就绪事件并报告提前退出或超时。

旧运行时只登记为待清理项，不和更新事务一起删除。状态损坏时，当前新布局状态和运行时会隔离到带元数据的 `runtime/recovery/repair-*`；修复失败会回滚，成功后留给用户检查。

`maintenance cleanup` 显示每项类型、状态、大小、原因和完整路径。严格识别且超过 24 小时的临时项可批量清理；当前 updater 运行副本可立即重试清理；近期项目禁止删除。恢复备份、未登记运行时和旧版路径只能逐项查看、用文件管理器打开，并在二次确认后永久删除。扫描后内容变化、符号链接或特殊文件都会使删除失败。
